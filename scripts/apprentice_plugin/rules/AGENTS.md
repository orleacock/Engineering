# Apprentice Multi-Backend Sidecar Routing

- Never call `127.0.0.1:1234`, integer/hex loopback encodings, Bionic AppImage, or `lms` lifecycle commands directly; route local offloads via `apprentice` MCP tools (`apprentice_control`, `apprentice_digest`, `apprentice_repo_audit`, `apprentice_stage_patch`, `apprentice_shadow_review`) or `apprentice_engine.py`, and include a 1-line `[APPRENTICE NOTICE]` with `Apprentice Calls = <clean>/<corrected> (healed=<healed>) [...]` whenever Apprentice is opened, loaded, or called.
- Whenever a `<SYSTEM_MESSAGE>` reports `OFFLINE` or `UNLOADED`, include the `[APPRENTICE NOTICE]` banner in your user-facing response offering to load/start the active backend remotely via `apprentice_control` (`gpu-max`, `gpu-daily`, or `cpu-bg`) upon user confirmation.
- Offload with `effort="auto"` as default (runs `STANDARD` for single-file/extract/`stage_patch` calls `<=2` concurrent `async_job=True`; auto-escalates cross-file contradiction audits to Single-Shot `HIGH` `<=54KB` or Lossless Map=`STANDARD` -> Reduce=`HIGH` `8192`-cap `>54KB`). Keep `verify_claims=True` default (supports `include_git_diff` via `.patch` mount), launch `apprentice_shadow_review(async_job=True)` for parallel CPU-oracle + semantic second-eyes critique, and collect async jobs with `apprentice_control(action="job-collect-any"|"job-collect", job_ids=[...], wait_seconds=120)`.
- Record verdicts via `apprentice_control(action="verdict", ...)` or `prev_call_id`/`prev_verdict`, never reset epochs (`scorecard-reset`) without `user_confirmed=True`, and verify drafts before promoting past `Quarantine/`.
