# Workbook & Template Structural Repair Workflow

Version: 2.2.3
Status: Current
Document ID: NEA-WF-005
Logical Name: Workbook_Repair_Workflow
Owner: NetCom Technical Services

## Purpose

This Workflow defines the step-by-step operational runbook used by the **NEA Repair Tool (`NEA-AGT-005`)** to diagnose and non-destructively repair structural Excel/OpenXML defects across NetCom project deliverable workbooks (`BOM_Materials_Master`, `Cable_Running_List`, and `Project_Cover_Sheet`) without altering engineer-entered project scope, quantities, or cable run data.

Engineers are routed to `NEA Repair Tool` whenever `NEA Package Reviewer` (or any builder agent) emits a `🔄 [CROSS-DUTY -> NEA Repair Tool]` advisory for overwritten formulas, broken Cover Sheet links, fragmented `<dataValidation>` / `<x14:dataValidation>` dropdowns, truncated `_FilterDatabase` AutoFilters (`[4E]`), or template modernization items (`TPL-##`, `GOV-002`, `GOV-006`, `GOV-007`).

---

## 1. Non-Destructive Repair Boundary (Project Data Lock)

1. **Zero Alteration of Engineer Project Data**:
   - **On `BOM_Materials_Master`**: Never alter user-entered values in `Project BOM` **Column `B` (`MB P/N`)**, **Column `C` (`Qty`)**, or **Column `J` (`Notes`)**, and never alter `Cover Sheet` metadata inputs (`D10:D24`, `H24`).
   - **On `Cable_Running_List`**: Never alter, delete, or reorder active cable run records across `Rows 3+` (`Columns A:P`), and never add a 17th per-row `Cable Run Status` column (`GOV-005`).
2. **Repair Scope (Plumbing, Formulas & OpenXML Extensions Only)**:
   - Restore overwritten or missing `<f>` formulas in formula-locked cells (`Project BOM` `Column A`, `Columns D:I`, `B2, E2, H2, E4`; `Cover Sheet!B30:C30`; `Lists!H1`; `CRL Summary!B17:B38`).
   - Heal fragmented or split-column `<dataValidation>` and `<extLst>` (`<x14:dataValidation>`) dropdown rules across `Rows 3..1087`.
   - Normalize truncated `_xlnm._FilterDatabase` AutoFilter ranges (`$A$2:$P$1087`).
   - Apply authorized `TPL-##` template upgrades (`GOV-002` unit-segregated summary metrics; `GOV-006` Cover Sheet parity links).

---

## 2. Step-by-Step Repair Procedure (Code Interpreter)

### Step 1 — Run Scoped Structural Diagnostic (`scripts/inspect_nea_workbooks.py --scope repair`)
1. On Turn 1 in Code Interpreter, execute:
   ```bash
   python3 scripts/inspect_nea_workbooks.py . --scope repair
   ```
2. Inspect ONLY the structural workbook mechanics output (`NEA Repair Tool` never audits project engineering deliverables or emits sister-agent deliverable advisories):
   - **Section 1**: `Cover Sheet!B30:C30` static overrides (`Rev` / `Date` decoupled from `H24` / `D24`) and `GOV-006` parity gaps.
   - **Section 2 (`--scope repair`)**:
     - `Project BOM` `Formula Overwrites in A8:I155`, Header Banner (`B2, E2, H2, E4`), and `G4` mixed-UOM sum (`GOV-002`).
     - `tblMaterials` table boundary (`$A$3:$G$508` vs oversized `$A$3:$G$600` causing 92 zero-spill entries in `Lists!H1#` under `GOV-007`) and `Fiber Assemblies!H` Status DataValidation `sqref` (`H4:H1258`).
     - `Cable Running List` `Data Validation, Dropdown & AutoFilter Integrity` (`[FRAGMENTED_DV_SQREF]`, `[SPLIT_COLUMN_DV_MISMATCH]`, `[TRUNCATED_AUTOFILTER]`).

### Step 2 — Execute Automated Non-Destructive OpenXML Repair (`--repair`)
1. Run the built-in deterministic repair engine in Code Interpreter:
   ```bash
   python3 scripts/inspect_nea_workbooks.py . --repair --out-dir Repaired_Workbooks
   ```
2. Automated `--repair` actions performed without touching any engineer data cells:
   - **Restores `Cover Sheet!B30:C30`**: `B30` = `=IF($H$24="","",$H$24)`, `C30` = `=IF($D$24="","",$D$24)`.
   - **Rescales `tblMaterials` & Hardens `Lists!H1` (`GOV-007`)**: Trims `xl/tables/table1.xml` `ref` to `A3:G<last_row>` (`A3:G508`) and adds `<>0` filter to `Lists!H1` so empty table rows never spill `"0"` into `BOMPartNumbers`.
   - **Expands `Fiber Assemblies!H` DataValidation**: Expands `sqref="H4:H286"` to `sqref="H4:H1258"`.
   - **Normalizes `CRL` AutoFilter & Preserves `<extLst>`**: Ensures `<autoFilter ref="A2:P1087">` / `_xlnm._FilterDatabase` and `<x14:dataValidations>` remain intact.

### Step 3 — Verify Repair Integrity (`--verify-write`) & Return Repaired Workbooks
1. Confirm `python3 scripts/inspect_nea_workbooks.py --verify-write <orig.xlsx> <repaired.xlsx>` outputs:
   - `Status: PASS` and `Write Verification Token: NEA-WRT-[12-hex]`
   - `Protected Formula Check (<f>): PASS (0 formulas overwritten)`
   - `OpenXML <extLst> Auto-Preservation: INTACT / RESTORED`
2. Present a concise **Workbook Repair Summary & Receipt** (`Before -> After SHA-256`, `Formulas Restored`, `OpenXML Validations / Table Bounds Repaired`, `NEA-WRT-...` token), provide the **downloadable repaired `.xlsx` file(s)**, and include a single-line handoff note to return to the active Builder or **`NEA Package Reviewer`** (do **not** list project deliverable findings for `BOM Builder`, `CRL Builder`, or `Catalog Manager`).
