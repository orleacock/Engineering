### `LL-NEA-01` [TIER2] [TRAP] — Overcoming M365 Copilot OneDrive Graph Latency & Ephemeral Container Boundaries
- **Symptom / Trap:** Connecting live `.xlsx` deliverables via OneDrive/SharePoint Knowledge links caused two severe failures: (1) Excel edits took minutes to hours to propagate through the asynchronous Microsoft Graph search index, and (2) Graph RAG text chunking could not evaluate OpenXML `<f>` (including `<f t="shared" si="..."/>`) vs. cached `<v>` values or 3-tier `XLOOKUP` chains. Additionally, Code Interpreter runs in an isolated Azure container (`16 MB` upload cap) that cannot write back directly to OneDrive.
- **Root Cause:** M365 Copilot separates declarative SharePoint Knowledge indexing (asynchronous semantic search) from Code Interpreter file attachments (synchronous container mount at `/mnt/data/`).
- **Verified Resolution & Permanent Guardrail (`GOV-015`, `GOV-017`):** Engineers upload live `.xlsx` deliverables **directly into the Copilot chat turn** (`+ Upload from device`), mounting exact bytes in `/mnt/data/` with `0` indexing latency; Mode 2 edits/repairs run `--verify-write ORIG EDITED` (`NEA-WRT-<12hex>`) inside Code Interpreter and return a downloadable `.xlsx` artifact in chat ([`NetCom_Engineering_Assistant`](NetCom_Engineering_Assistant.md)).

### `LL-NEA-02` [TIER2] [TRAP] — Solving the `8,000`-Char Instruction Cap, Headroom Margin, `"2.2.3"` Semver Lock & `.txt` Knowledge Indexing
- **Symptom / Trap:** A single monolithic prompt exceeded M365 Agent Builder's `8,000`-character hard cap; `.zip` uploads with alphanumeric version `"2.0a"` or unexpanded `$[file('...')]` macros failed M365 schema validation; and raw `.md` or `.py` files uploaded to `Knowledge/` were skipped or poorly indexed by Graph.
- **Root Cause:** Agent Builder enforces `Instructions <= 8,000` chars (`Name <= 30`, `Description <= 1,000`), strict numeric `X.Y.Z` semver (`"2.2.3"`), inline string compilation, and native `.txt`/`.docx`/`.pdf`/`.xlsx` indexing. Prompts tuned close to `8,000` chars without headroom break when incremental capabilities land (e.g., adding Option C `2D Digital Grid Snapshot` rules grew `NEA_Timesheet_Consolidator` from `5,220` to `6,206` chars, and `GOV-006` + `edit_nea_workbooks.py` updates grew `Package Reviewer`/`BOM`/`CRL`/`Repair` to `5,463`/`3,970`/`3,596`/`3,725` chars stripped).
- **Verified Resolution & Permanent Guardrail:** `Scripts/build_copilot_agents.py` (`NEA-SCR-002`) compiles the **6-Agent Modular Specialist Suite** under an automated **`<= 6,500`-char NEA headroom ceiling** (`>= 1,500` chars below M365's `8,000` cap; currently `3,596`–`6,206` chars / `45.0%`–`77.6%`), pairing directional `🔄 [CROSS-DUTY -> <Agent>]` advisories with auto-synced `.txt` Knowledge packs (`Knowledge/*.txt`; [`NetCom_Engineering_Assistant`](NetCom_Engineering_Assistant.md)).

### `LL-NEA-04` [TIER2] [TRAP] — Preventing `openpyxl.save()` from Stripping Cross-Sheet `<extLst>` DataValidations
- **Symptom / Trap:** Saving `BOM_Materials_Master_Template.xlsx` or `Cable_Running_List_Template.xlsx` with standard `openpyxl.save()` silently stripped `<extLst>` (`x14:dataValidations` cross-sheet dropdowns referencing `Lists`) and left fragmented `DataValidation` ranges (`Rows 3..1087`) or broken `_FilterDatabase` definitions.
- **Root Cause:** `openpyxl` drops unrecognized `<extLst>` worksheet extension trees during XML re-serialization.
- **Verified Resolution & Permanent Guardrail:** Built `preserve_openxml_extensions()`, `[4E]` OpenXML DataValidation/AutoFilter auditing, `--repair [--out-dir <dir>]`, and `--verify-write ORIG EDITED` (`NEA-WRT-<12hex>`) into `Scripts/inspect_nea_workbooks.py` (`NEA-SCR-001`) and `nea-workbook-entry-guard` (`NEA-SKL-002`; [`NetCom_Engineering_Assistant`](NetCom_Engineering_Assistant.md)).

### `LL-NEA-06` [TIER2] [TRAP] — Preventing Windows Desktop Excel OpenXML "File is Corrupt" Rejections on Generated Multi-Tab Workbooks
- **Symptom / Trap:** Initial `Week_of_10-25_to_10-31.xlsx` workbooks generated by cloning `Timesheet_Template.xlsx` passed basic Python `ET.fromstring()` checks, yet Windows Desktop Excel refused to open them (`"The file is corrupt and cannot be opened"`).
- **Root Cause:** Six ECMA-376 OpenXML serialization defects produced by Python's `xml.etree.ElementTree.tostring()` and zip cloning: (1) `ET.tostring()` stripped `xmlns:x14ac`/`xmlns:xr`/`xmlns:xr2`/`xmlns:xr3` declared inside `mc:Ignorable="..."` on `<worksheet>` and stripped `xmlns:x14`/`xmlns:x15` from `<ext uri="...">` blocks in `xl/styles.xml`; (2) `ET.tostring()` injected `<ns0:Types>` and `<ns0:Relationships>` prefixes into `[Content_Types].xml` and `xl/_rels/workbook.xml.rels`; (3) `<definedNames>` retained dangling references to the deleted `'Expense Report'` tab; (4) cloned employee tabs shared a single `xl/drawings/drawing1.xml`, identical `xr:uid`, and `codeName="Sheet13"`; (5) dynamically appended cells (`C10`, `B25`) were appended at the end of `<row>` out of ascending column order; and (6) passing stale `ZipInfo` objects from `zin.infolist()` to `zout.writestr(item, data)` preserved stale CRC/size headers.
- **Verified Resolution & Permanent Guardrail (`GOV-018`):** Replaced `ElementTree` package serialization with deterministic UTF-8 XML builders (`_format_worksheet_xml_bytes()`, `SharedStringTable`, `_sort_sheetdata_rows_and_cells()`, per-sheet `drawing{idx}.xml` + unique `xr:uid`, and `validate_openxml_package_integrity()` inside `run_verify_write()`), verified by `xmllint --noout` and confirmed opening cleanly in Windows Desktop Excel ([`NetCom_Engineering_Assistant_Module_Launchpad`](NetCom_Engineering_Assistant_Module_Launchpad.md)).

### `LL-NEA-07` [TIER2] [TRAP] — Multi-Media Timesheet OCR Staging, Key Normalization & Non-Target Tab/Page Pruning
- **Symptom / Trap:** Field timesheet submissions arrive as mixed digital `.xlsx` files (containing a second `Expense Report` tab and a missing `AG35` Job Slot 10 `REG` formula), multi-page scanned `.pdf` packets (interleaving employee timesheets with mileage sheets, Home Depot receipts, and vendor invoices), and photos—where minor LLM JSON key variations (`"job"` vs. `"job_name"`, `"days"` vs. `"hours"`, `"Tues"` vs. `"tue"`) during manifest staging risked dropping job hours.
- **Root Cause:** Unfiltered multi-page PDF ingestion and rigid JSON key expectations between the LLM OCR pass and the deterministic OpenXML writer.
- **Verified Resolution & Permanent Guardrail (`GOV-018`):** Built `Templates/Timesheet_Template.xlsx` (`NEA-TPL-004`, `Expense Report` stripped, `AG35` restored, styled with the NetCom Corporate Color Palette `cellXfs 217..239`), enforced page-level classification and pruning of non-timesheet pages/tabs in `NEA Timesheet Consolidator` (`NEA-AGT-006`), and added `normalize_timesheet_emp_record()` in `Scripts/inspect_nea_workbooks.py` (`--consolidate`)—verified in Cold-Start `Blind-Light` (`24831c6b`) and `Blind-Light+faults` (`1/1` injected formula corruption caught; [`NetCom_Engineering_Assistant`](NetCom_Engineering_Assistant.md)).
