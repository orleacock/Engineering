# Engineering Memory — Dual-Mode Engineering Memory Hub

> **Supreme Governing Priority Hierarchy (`1. Accuracy & Truth -> 2. Efficiency -> 3. Data Safety -> 4. Speed`)**
> This memory tree operates identically in **Headless Mode** (standard Markdown in VS Code, Cursor, GitHub, or terminal) and **Obsidian Vault Mode** (`memory_mode: obsidian`). All internal links use portable POSIX relative paths (`[Label](relative/path.md)`) across Windows, macOS, and Linux.

---

## 1. Directory & Containment Architecture

| Directory | Purpose & Single-Writer Governance |
| :--- | :--- |
| [`Directory/`](Directory/Directory_Index.md) | Turn-1 location lookup maps (`Directory_Index.md` + entity-isolated `<Entity>_Directory.md` box trees) maintained automatically at `pre-commit-gate` Stage X so agents resolve paths without `ls`/`find` probes. |
| [`Projects/`](Projects/) | Self-contained per-project folders (`Projects/<Project>/`). Each folder holds `<Project>.md` (Hub + `AUTO-TREE`), domain telemetry (`<Project>_Hardware.md` and/or `<Project>_Software.md`), `<Project>_Lessons_Learned.md`, custom [`Templates/`](Templates/), and [`Quarantine/`](Projects/). |
| [`Tasks/`](Tasks/) | Single-writer, entity-partitioned task umbrellas (`Tasks/<Entity>_Tasks.md`). All active checkboxes (`- [ ]`) live here so project dossiers never drift out of sync. |
| [`Standards_and_Specs/`](Standards_and_Specs/) | Locked engineering standards, design rules, and verified cross-project reference specifications. |
| [`Templates/`](Templates/) | Canonical master templates for project hubs, hardware/software telemetry, lessons learned, task umbrellas, quarantine notes, and reusable project deliverables. |
| [`Diagrams/`](Diagrams/) | Deterministic `.svg` (and opt-in `.png`) technical diagrams generated by `visual-studio` (`render_diagram.py`). |

---

## 2. Multi-Customer / Peer-Entity Isolation Law

- Every project dossier in `Projects/<Project>/<Project>.md` declares an explicit `entity:` and `compartment:` in YAML frontmatter.
- **Zero Cross-Entity Contamination**: When working on a project owned by `entity: Client_A`, the AI assistant and scripts must **never** link to, read, cite, or borrow specifications from any `Projects/<Other>/` or `Tasks/<Other>_Tasks.md` owned by `entity: Client_B` unless explicitly authorized by the user in the active turn.
